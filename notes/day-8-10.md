# Day 8–10 — Scenario library shipped

## Done
- `src/lib/scenarios.ts` — 5 curated scenarios (DB pool exhaustion, OOM deploy, dependency timeout, DNS, cache stampede), each with `expected_root_cause` and `expected_severity` for later eval
- `scripts/seed-scenarios.ts` + `npm run seed:scenarios` — idempotent upsert by slug
- `/scenarios` page — category badge, expected severity badge, expandable raw context
- `<RunScenarioButton />` → `POST /api/scenarios/[slug]/run` → generates analysis, persists, redirects to detail page
- Bundled Days 8–10 because each was small; the actual work was researching realistic SRE scenarios.

## Decisions
- Scenarios live in code, not in DB seed only — they're the regression suite, so they need to be version-controlled and reviewable in PRs
- The seed script `upsert`s by slug so it's safe to re-run after every edit
- Each scenario is detailed enough (~15–25 lines of context with metrics, logs, deploy history, on-call notes) to expose prompt weaknesses; flimsy scenarios won't differentiate v1 vs v2
